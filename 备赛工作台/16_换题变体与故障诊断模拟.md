## 2. 题目区 B：展馆物品递送【原创模拟设定】

### B1 需求与资源

一台带机械臂的移动机器人接到指令：“把补给桌的蓝色水杯送到接待桌的白色托盘，然后返回。”机器人使用头部RGB-D相机，抓取时相机相对基座固定。桌上另有红杯和蓝盒；颜色相同不能替代物体类别匹配。

已提供：可定位的地图、相机内参、正确标定、机械臂运动学与碰撞模型；尚须选择/配置实例分割、6D抓取、导航与状态机。本模拟不要求重新标定15次，也不要求自行训练特定次数；不能将其他练习的数量要求搬进来。

地图坐标采用米，偏航角采用弧度，逆时针为正：

| 航点 | x | y | yaw | 用途 |
|---|---:|---:|---:|---|
| HOME | 0 | 0 | 0 | 起终点 |
| PICK | 3 | 2 | 0 | 面向补给桌 |
| DROP | 6 | 2 | 3.14159265 | 面向接待桌 |

题设保证这三个站位无障碍且能进行相应观察；不要求猜测未给出的地图。每次到点须同时满足位置误差≤0.10m、最短角差≤0.10rad。抓取/放置期间底盘静止；搬运时手臂进入已给定的携物姿态。

### B2 接口约定

以下字段只为本模拟定义，不冒充平台原有字段。分割输出`label、instance_id、mask`，标签明确为`blue_cup、red_cup、blue_box、white_tray`，本题每类仅一个实例；由同帧对齐深度裁出相机系点云；6D模块输出`PoseStamped`，其`frame_id=camera`，本题规定候选表示**期望TCP位姿**而非物体中心或腕关节位姿。机械臂接口接收**基座系TCP目标位姿**，内部已处理腕部与TCP关系，外部不要再补一次工具偏置。

变换记号`T_base_camera`表示“相机系坐标变成基座系坐标”。本题为单位旋转、平移`(0.20,0,0.80)m`。选中候选在相机系的位置为`(0.30,0.10,0.20)m`、姿态为单位旋转。白托盘位置须到DROP后重新观察；不提供可直接复用的旧目标点。

每项异步命令与结果都带`robot_id、stage、command_id`。完成结果另外带`success、reason`。只有匹配当前命令且实际成功的结果才能推进；本题夹持确认和入盘确认均由给定执行接口提供。失败允许当前阶段重试一次，仍失败则停在失败态，不宣布整任务完成。

### B3 作答要求

画出完整流程，列出四节点职责；算出TCP目标位置；解释为什么到接待桌后要重新观察。为“错物体、空抓取候选、规划失败、旧回调重放”分别写处理方法。给出记录表应包含的字段，以及怎样判断整次递送成功。

自测100分：目标与感知链25；坐标与规划25；状态机及失败处理30；到点/朝向/最终验收20。每部分满分条件在答案区列明；这些分值不是省赛预测权重。

## 3. 题目区 C：导览与安全展示【原创模拟设定】

### C1 需求与事件

一台双足机器人从起点带访客前往展区。到演示位并面向观众后，执行15秒参考舞蹈，结束后回起点报告。路径含一个可通行缓坡。题设提供地图、航点、可用走路策略及一份30Hz关节角轨迹；控制器以50Hz读取目标。舞蹈区平整且边界已知，不要求在坡上跳舞。

本卷到点条件为位置误差≤0.10m、最短角差≤0.10rad；舞蹈合格条件为连续15秒无摔倒、无关节超限，且全部关节与时刻的角度跟踪RMSE≤0.15rad。RMSE是先对误差平方求平均再开根号。这些阈值只用于本卷验收，不是官方舞蹈评分阈值。

行为模块每0.1秒输出当前同一被跟踪访客的事件和置信度。**连续三个有效样本都是`fall`且置信度≥0.80**时触发安全暂停；任一低置信度或不同事件使计数归零。缺测也归零，不能把三个不连续检测拼接。本题不包含人脸身份识别或OCR。

触发后停止推进任务，调用已提供的安全停止接口并等待确认，报告“检测到异常，演示暂停”。收到显式`clear`指令才允许恢复；恢复后还要重新确认位置与朝向。若打断舞蹈，本题规定从舞蹈开头重做15秒，不能把中断前后片段拼成完整成功。

### C2 作答要求

写出正常与异常状态分支；说明何时使用走路策略、何时切换舞蹈策略，以及为什么切换前要确认静止稳定。说明数据重采样与关节单位检查；给出动作完成的验收条件。以下序列每项间隔0.1秒，判断何时触发：

```text
fall .91 → fall .88 → normal .99 → fall .95 → fall .85 → fall .90
```

自测100分：导航与动作衔接30；事件触发及暂停恢复30；轨迹与控制20；成功反馈20。不得以“消息发出”代替动作结束，不得承诺已有平台能添加本题安全接口。

## 4. 题目区 D：八道故障与源码改错【原创模拟设定】

每题10分，共80分，独立于B/C。先写“最早可确认的错误在哪层”，再给修正；未知之处允许明确写出需要什么证据。

### D1 步态周期

代码为`phase=(k % t1)/t1`，`k`每个控制步加1，`dt=0.02s`、`t1=30`。完整周期和频率是多少？若右腿相对左腿差半个周期，时间差是多少？直接把`t1`读成30秒为什么错误？

### D2 舞蹈重采样

输入451行，时间为`0,1/30,...,15`秒；角度单位为弧度。控制器每0.02秒读取一行。直接播放原表会怎样？保持首尾时间不变应生成多少行？如何处理角度跨越`+π/-π`边界？

### D3 奖励正负号

`E`是非负动作跟踪平方误差，`upright∈[0,1]`越大越直立，`energy`和`smooth_cost`都是非负代价，`fallen∈{0,1}`。原式如下，要求保留系数绝对值并修正方向：

```python
reward = exp(-E / 0.25) - 2.0 * upright
reward += 0.01 * energy + 0.05 * smooth_cost + 10.0 * fallen
```

再计算`E=0、upright=1、energy=10、smooth_cost=2、fallen=0`的修正后奖励。

### D4 更换建图算法

正式题出现Point-LIO或LIO-SAM。队友把FAST-LIO的整份参数原封不动粘入，理由是“都是激光惯性里程计”。能否验收？列出新配置前最先核对的项目；题面没有新算法schema时，能否给出一套保证有效的数值？

### D5 失败回调也前进

代码没有核对消息身份、重复消息或成功标志：

```python
def on_finish(msg):
    state += 1
    send_next_task(state)
```

请按B2的接口约定给出修正逻辑；失败重试与重复成功消息分别如何处理？

### D6 重复TF

视觉节点已经输出`frame_id=base`、位置`(0.50,0.10,1.00)`。机械臂节点却又把它声明成camera系，套用B2变换一次。错误结果是多少？正确数据流应怎样设计？

### D7 抓取点为空与规划失败

两条**合成日志**分别为：甲`分割成功；抓取点=[]`；乙`分割成功；抓取目标非空；规划失败`。队友建议把两者规划时间从3秒统一改成5秒，预计都能修好。指出结论哪里不成立，给出各自排查顺序。再说明“放置目标位已算出”能否证明实际放置成功。

### D8 到了点却背对展台

地图以+x向东、+y向北，机器人本体+x为正前方。站位`(2,3)`，展板中心`(2,5)`，航点却填`yaw=-π/2`。只修改什么能使机器人面向展板？如果站位落在障碍膨胀区，仅修改朝向是否足够？

## 5. 标准答案 B【原创模拟设定】

### B答案：完整流程与判定点

```text
接单并核对目标 → 导航PICK → 位置/朝向达标并停止底盘
→ RGB-D采集 → 指定实例分割 → 同帧深度裁剪/点云
→ 6D候选筛选 → 相机系转基座系 → IK/碰撞检查与路径规划
→ 执行到抓取位 → 闭爪并确认夹持 → 携物姿态
→ 导航DROP → 到点并停止 → 重新定位白托盘
→ 规划放置路径 → 执行 → 张爪并确认物品入盘
→ 安全收臂 → 返回HOME并核对位姿 → 报告任务成功
```

`master`记录阶段和目标并分发；`nav`处理目标位姿与到点结果；`vision`返回正确实例、点云或目标位姿；`arm`完成候选、变换、规划和执行反馈。节点名可不同，接口职责不能遗漏。若6D单独放在vision，也须明确输出坐标系并避免另一节点重复估计/变换。

由于旋转为单位阵，目标位置为`(0.30,0.10,0.20)+(0.20,0,0.80)=(0.50,0.10,1.00)m`，姿态仍为单位旋转。该数值仅由模拟题设得出，不是平台通用抓取点。TCP偏置已在接口内部，不能再叠加。到DROP后机器人基座在地图中的位置和方向已变；PICK处观测不能当成现在相机中的白托盘位置。按题意重新采集并变换，保留帧名和时间戳。

四类异常的标准处理：目标标签与实例不符合“蓝色水杯”就不发抓取；候选为空就停止该阶段并检查目标裁剪、有效深度、点云及候选过滤；候选存在但规划失败，检查规划组/末端、当前状态、IK、碰撞与路径约束；旧或重复回调丢弃。重试仍失败进入失败态，不能放行后续成功流程。

记录至少含阶段、命令ID、目标实例、数据时间/坐标系、规划结果、执行结果、失败原因、重试次数及最后状态。完整成功必须是**正确物品已入正确托盘、机器人已回HOME、每个必要阶段成功且无未解决失败**。不能只凭视觉识别或夹爪闭合判定。

自测判定：25分感知须对象/实例/同帧深度/点云/6D均正确，每项5；25分坐标规划须变换方向、位置计算、TCP约定、IK与碰撞、重新观察均正确，每项5；30分状态机须匹配回调、成功推进、去重、限次重试、失败停留、最终结果，各5；20分导航验收须三个航点、朝向、静止与携物切换、实际入盘返航，各5。

## 6. 标准答案 C【原创模拟设定】

正常状态为`待命→导览导航→到位稳定→舞蹈→结束稳定→返航→完成`。导航阶段走路策略接受运动需求；到达演示位并满足位姿要求后停止导航速度输出，确认稳定，再启用舞蹈策略。两种策略不能同时向同一执行接口争夺控制。舞蹈结束后安全恢复站立，再切回走路返航。

异常监测贯穿活动阶段。计数依次是`1、2、0、1、2、3`，在第六个样本触发。进入`暂停中`并请求安全停止；收到停止确认后成为`已暂停`并报告。没有确认就不能声称机器人已停稳。`clear`只允许开始恢复流程，不代表原任务自动成功；重新检查位姿与稳定条件，若舞蹈被打断则从头完成15秒。

轨迹按实际时间重采样到50Hz，逐关节检查顺序、数量、角度单位、限位及相邻目标变化。不能用“每行读快一点”冒充重采样。具体计算见D2。完成要求包括规定15秒连续完整动作、全部关节与时刻的角度跟踪RMSE≤0.15rad、无摔倒或超限、没有被未解除的暂停打断，并收到匹配本次舞蹈命令的成功反馈；之后还要返航，才能宣布整次演示完成。

自测判定：导航与动作衔接三项各10分：到位朝向、先稳定再切换、结束后安全返航；事件三项各10分：连续计数正确、等待停止确认、显式解除并重做；轨迹两项各10分：时长不变、单位/关节/限位核查；反馈两项各10分：动作真实完成、整任务完成条件独立于动作阶段。

## 7. 标准答案 D【原创模拟设定】

**D1：** 周期`30×0.02=0.60s`，频率约`1.667Hz`，半周期`0.30s`。`t1`在给定代码中是步数，不是秒。若真实源码定义不同，要重新按代码推导。本题算对周期/频率/半周期6分，说明单位与实现依赖4分。

**D2：** 原表直接以50Hz播放，首末样本时间间隔变为`450/50=9s`。应在`0,0.02,...,15`采样，共`15×50+1=751`行；按原时间轴插值，而非简单复制行。周期角先按连续运动解包再插值；受限关节须结合实际限位与轨迹语义，不能盲目选择跨限位的“最短角”。时间与行数6分，插值/角度处理4分。

**D3：** 正确示例：

```python
reward = exp(-E / 0.25) + 2.0 * upright
reward -= 0.01 * energy + 0.05 * smooth_cost + 10.0 * fallen
```

代入得`1+2-0.1-0.1=2.8`。误差越大指数项越小；能耗、抖动和摔倒扣分，直立加分。本题符号与数值各5分。真实工程若代价函数内部已带负号，外层不能重复取负；本题已明确它们非负，故答案确定。

**D4：** 不能验收。先核对新版本的参数schema及默认配置、支持的激光/IMU类型、话题和消息字段、时间同步与单位、外参方向、坐标系和输出地图接口，再识别哪些旧概念仍对应、哪些字段已改名或不存在。之后按新配置做受控验证，检查初始化、轨迹连续性、地图和导航兼容性。此处仅作方案，不实际运行。没有schema不能杜撰保证有效的数值。识别迁移风险3分、核对项目5分、验证与未知边界2分。

**D5：** 用状态转移表而非盲目`state+1`。下面是离线伪代码，非平台可直接粘贴源码：

```python
def on_finish(msg):
    key = (msg.robot_id, msg.stage, msg.command_id)
    if key != pending_key or key in handled:
        return
    handled.add(key)
    if not msg.success:
        retry_same_stage_with_new_id_or_enter_failed(msg.reason)
        return
    # success须代表题设约定的实际完成，而非仅“已接收命令”
    enter_state_and_send(next_state[current_state])
```

失败保留当前任务阶段；重试使用新ID，第二次失败结束本阶段；重复成功消息只接受一次。实现还需使检查、标记和状态更新避免并发重复执行。身份/去重4分，失败分支3分，实际成功及状态更新3分。

**D6：** 错误位置变成`(0.70,0.10,1.80)`，平移被加两次。方案一：vision返回camera系位姿，arm转一次；方案二：vision已转base，arm直接消费base位姿。禁止改标签冒充变换。计算4分，帧约定与单次变换6分；若真实矩阵含旋转，重复变换会同时改变位置与姿态，不能仅减一个常数修补。

**D7：** 甲最早确认在“合理抓取候选未产生”，先检查选中实例、裁剪/深度对齐、有效点云、模型输入与过滤/标注；不能由空列表直接断言唯一根因。乙已过候选存在检查，优先核对坐标单位/姿态、规划组与末端、当前状态、可达性、碰撞和约束，再考虑规划预算。增加时间可能有用但不保证修复，更不会自动补出甲的候选。放置目标存在仅说明计算分支有输出，仍须执行与入盒证据。分层4分、顺序4分、结果边界2分。真实失败对照见[12实测手册](12_全任务实测与排错手册.md)任务11/12；本题合成日志不新增实测成绩。

**D8：** 朝向为`atan2(5-3,2-2)=+π/2`。位置可保持`(2,3)`，前提是站位本身可用。若落在障碍膨胀区，还须选满足底盘安全间距、可达性与服务距离的新站位，再按新站位计算朝向。不能只旋转箭头便宣布修好，也不应无依据压低安全距离。方向计算5分，位置与朝向独立验收5分。

## 8. 做完以后怎样复盘

把每个错误归到“需求理解、数据类型、坐标、规划、执行、完成反馈”之一，写清下一次遇到什么证据才判成功。若能看懂答案却不能独立画出流程，再回读[11速通路线](11_速通版完整学习路线.md)；若参数与平台旧记录冲突，以[12最新实测](12_全任务实测与排错手册.md)查证，不把原创题的数值覆盖到真实账号配置。

两套变体用于练迁移，不代表正式比赛一定出现递送、跌倒事件或这些状态数量。正式题开放后，先逐项核对资源是否预置、输入输出、对象、坐标约定、成功条件和评分，再决定哪些链路适用。
