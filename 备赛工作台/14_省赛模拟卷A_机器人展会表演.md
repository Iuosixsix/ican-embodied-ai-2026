## 1. 怎样模拟，才不把假场景当成真实平台

本卷提供两个层次：

1. **现在即可做的离线演练：** 读题、填写决策单、算坐标、选择模型、连数据流、追踪回调、诊断报告。附[完整题设 JSON](sources/mock_20261023/exam_a_fixture.json)与[空白答题单](sources/mock_20261023/答题单.md)，无需训练或登录。
2. **以后由你自行开展的对应练习：** 在现有任务3、9、11/12、14中复刻相同操作类型，保留各自真实机器人、数据、地图与标定。本卷不能导入平台变出新展馆；不把分开的练习伪称已连成一个综合仿真。

当前代理实操继续暂停。本卷不要求点击任何会锁定实验的最终评分按钮。真实比赛的最后交卷仍按官方规则；离线模拟用“完成答题单”代替点击。

**资源边界：** 题设中的 E 机器人是具备行走、动作展示、RGB-D感知与双臂能力的抽象考试机器人，不承诺正式型号。任务3用H1练舞蹈，任务14用R1/G1练集成；两者模型不能直接互换。JSON是教学数据，不是URDF、地图包、训练集、轨迹文件或可导入的ROS工程。未提供的原始资源，平台练习时用该题自带资源，不能假称已训练本卷模型。

## 2. 需求书与资源清单

**【模拟设定】** 展会机器人 E 收到一次启动指令后，完成下列连续任务：

`待机 → 到表演区并朝向观众 → 完成指定舞蹈 → 到取物台 → 按指令识别并抓取水壶 → 到放置台 → 将水壶放入蓝盒 → 回起点 → 确认全部成功后播报结束`

不允许把“发出了指令”“模型指标合格”“某函数执行了”当成动作已经成功。任一步失败，进入可诊断的失败分支，不宣称整场展示完成。单次只允许一个导航或机械臂动作处于等待完成状态。

| 资源 | 本卷提供的内容 | 选手工作 |
|---|---|---|
| 机器人与传感器 | E的抽象能力、RGB-D输入；双臂逻辑映射见R题 | 核对模型和接口匹配，不自行拼接H1/G1权重 |
| 运动 | 三组候选模型评估数据、奖励伪代码 | 选型、补奖励、给出平台构建步骤 |
| 地图 | 12m×8m俯视教学坐标，0.05m/格，原点(0,0)，x向右、y向上 | 建图方案、航点位置及朝向、避障路线 |
| 视觉 | 三条检测输出、目标名、相机内参和一个深度值 | 选正确目标、构建点云/颜色两条数据流 |
| 标定 | 明确定义的相机到基座矩阵 | 算点变换并说明实际抓取还缺什么 |
| ROS | 借用练习14的字段及新增模拟舞蹈接口 | 完成消息合同、状态机、失败处理 |
| 报告 | 四段人工构造的失败事件 | 找最早失败环节，提出最小复验 |

**本卷模拟分值：运动20＋导航25＋视觉20＋集成35＝100分。** 这是教学配分，不是官方四模块权重；抓取在本卷计入集成，实际平台菜单归属以题面为准。

## 4. M：运动控制（20分）

### M1 构建决策单（6分）

按“观察→动作→奖励→重置→训练→选模型推理”列出操作顺序。用[12任务3](12_全任务实测与排错手册.md)已记录的H1基线作为**对应练习配置**：写出观察量、动作输出与平滑方式、重置的角度/位置偏差阈值（不是评分偏差档位）、训练步数/学习率/批量，并说明为什么不能把H1权重直接部署给E或G1。

真实入口映射：任务3“训练模型构建”→模型参数/训练→“查看”→选择模型→仿真→报告。具体页面名称和可选项可能变动，不能创造不存在的按钮。

|---|---:|---|---|
| A | 100M | 100%、100%、100% | 7.1%、7.4%、7.8% |
| B | 200M | 100%、100%、100% | 5.2%、5.4%、5.6% |
| C | 100M | 100%、92%、100% | 6.2%、6.0%、6.4% |

### M3 奖励与新增参数（6分）

模拟代码中 `pose_error_sq` 是归一化姿态均方误差，`action_delta_sq`是相邻动作变化量平方，均≥0；`alive`存活为1，否则0；两个权重均>0。

```python
reward = alive + w_pose * pose_error_sq + w_smooth * action_delta_sq
```

改正公式，使策略倾向于活着、跟随动作且减少突变。解释为何不能只奖励存活；再分别解释`buffer_size`、`batch_size`与PPO clip，说明它们不是机械臂运动速度或关节刚度。这里不要求猜出唯一最优数值。

## 5. N：定位导航（25分）

### N1 建图与算法变化（6分）

题设给出地图尺寸与分辨率，计算栅格宽高。列出从传感器/标定检查到建图、按算法支持检查回环或重访区域一致性、地图保存/转换、定位、规划、航点、导航验证的顺序。不能把所有LIO算法都当作自带回环模块。

如果正式建图菜单变成Point-LIO或LIO-SAM，旧FAST-LIO配置能否整卡照抄？写出至少三项要重新核对的输入/参数类别。只有名称变化、没有真实schema时不得自造数值。

### N2 航点与避障（10分）

坐标单位m，yaw单位rad；yaw=0朝+x，正向逆时针。

|---|---|---|
| home | (1,1) | (2,1) |
| stage | (3,1) | (3,0) |
| pick | (3,6) | (3,7) |
| place | (9,6) | (10,6) |

1. 写出四点yaw；用`atan2(目标y−当前y, 目标x−当前x)`解释。
2. 中央障碍占`[4,6]×[3,5]`；本卷按机器人半径0.25m＋安全余量0.15m作保守矩形膨胀。写出禁止机器人中心进入的区域。边界也视为不安全。

## 6. V：视觉与坐标（20分）

### V1 目标选择与数据流（8分）

指令是“取水壶”，当前模拟检测阈值0.50：

| id | 类别 | 置信度 | 矩形框(x1,y1,x2,y2) |

| d2 | 塑料碗 | 0.94 | (250,110,350,210) |
| d3 | 水壶 | 0.42 | (410,80,500,220) |

选出本次目标；画出“RGB-D→按目标类别筛选→裁剪/掩码→目标点云→6D位姿”的数据链，说明每一步输出类型，以及分类网络为什么不够。对比蓝盒定位分支：为什么它返回位置/位姿，不返回拿来抓取的水壶点云？

### V2 像素、相机、基座（6分）

**【模拟算例】** 本题独立于V1，不沿用V1的检测框。已完成畸变校正与RGB/深度配准；深度值是沿光轴的Z，不是斜距。`fx=fy=600px,cx=320px,cy=240px`，目标像素`(380,240)`，Z=1m。列向量约定：

```text
p_base = T_base_from_camera · p_camera
T_base_from_camera = [[1,0,0,0.2],
                      [0,1,0,0.0],
                      [0,0,1,0.5],
                      [0,0,0,1.0]]
```

求相机系、基座系三维点。再说明仅有这个点为什么仍不足以给出一个真实可执行的夹爪6D抓取姿态。若上游已经返回基座系位姿，下游还能再次乘这个矩阵吗？

### V3 数据与指标（6分）

模拟数据来自同一视频连续帧。在训练集和验证集随机混入相邻帧是否可靠？给出划分方法与至少三种应覆盖的变化。再判断：“分割mAP=.976，所以抓放必定成功”是否成立，写出三个后续可能失败的环节。

## 7. R：ROS集成、抓取与排错（35分）

### R1 消息合同与状态机（12分）

模拟采用4个功能节点master/nav/vision/arm；舞蹈执行器作为**新增模拟接口**，不声称任务14已有同名按钮。

| 通道 | 模拟字段 |
|---|---|
| `_nav` | `Navigation_Address`：字符串 |
| `_locate`服务 | 请求两个字符串：`Detect_Type`取“物体”或“颜色”，`Detect_Name`为对象名/颜色名；响应`Point_Cloud`为点云，`Pose`为位姿 |
| `_grab` | `Hand`：布尔，`Pcloud`：相机系点云 |
| `_deploy` | `Hand`：布尔，`Fpose`：基座系位姿 |
| `_dance`（模拟扩展） | `Model`：已核对适配性的模型标识 |
| `_finish` | 基础模式统一`Is_Finish`布尔；成功才为true |

本卷固定`Hand=false`→`left_arm/left_gripper`，true→右侧。**仅为本卷合同**，迁移真实G1必须同时核对发送端Hand和接收端条件，不能凭0/1猜左右。

本卷纸面抓取指定左手，**模拟假设**目标在左臂可达空间且抓放过程中可保持；因此取放都发false。这不是对真实机器人可达性的证明。视觉服务物体分支返回空点云、颜色分支返回无效位姿、或请求超过5秒未返回，均进F；5秒仅本卷设定，真实接口需读题核实。动作返回false或超时也进F，绝不转成成功。

补齐下表：每个状态说明当前等什么、成功后做什么、失败如何处理。状态编号为本卷原创，不是任务14原编号。

| 状态 | 已发出的操作 |
|---:|---|
| 0 | 待机，收到一次start才启动 |
| 1 | nav到stage |
| 2 | 执行舞蹈 |
| 3 | nav到pick |
| 4 | locate物体“水壶” |
| 5 | grab水壶 |
| 6 | nav到place |
| 7 | locate颜色“蓝色” |
| 8 | deploy水壶 |
| 9 | nav回home |
| 10 | 整体完成 |
| F | 失败/等待人工诊断，不发完成播报 |

解释哪些状态等视觉服务、哪些等动作完成。消息字段大小写、类型、来源坐标系必须一致。只有布尔完成标志时说明适用假设；若可扩展消息，提出防重复/旧回调办法，不能假定平台已支持新增字段。
