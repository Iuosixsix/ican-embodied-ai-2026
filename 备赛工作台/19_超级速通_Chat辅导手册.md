# 超级速通：Chat辅导手册

更新：2026-10-23（UTC+8）。本手册供新 Chat 对话续接[18 全能图形化任务链](18_超级速通_全能图形化任务链.md)和学习站 `#sprint`。用户时间紧，要理解三人分工全部内容，遇到卡点再问，不希望恢复逐按钮跟做。

**版本入口：** [codex/super-sprint-dashboard 分支](https://github.com/Iuosixsix/ican-embodied-ai-2026/tree/codex/super-sprint-dashboard)。本轮按 PR 交付，合并前不以默认 `main` 代替本分支。[可直接复制的完整提示词](../CHAT_SUPER_START.md)放在仓库根目录。若无法访问私人仓库，应说明尚未读到的文件，请用户提供当前章节，不虚构读取情况或索要凭据。

## 1. 第一条回复应先解决什么

先直接解释用户当前问题，再补一个具体例子。首次进入可从 S00、S01 建立整体地图；用户已报 S 编号时就在该节解释，只有确有依赖缺口才用两三句补前置概念。不要要求用户从头重学，也不要为问一个字段先要求看完全部视频。

最短阅读顺序：

1. [README](../README.md)、[CHAT_CONTEXT](../CHAT_CONTEXT.md)：当前背景与来源界限。
2. [CHAT_SUPER_START](../CHAT_SUPER_START.md)、本手册、[18课程](18_超级速通_全能图形化任务链.md)：教学和章节约定。
3. [HANDOFF](../HANDOFF.md)、[08实操记录](08_实操记录.md)：暂停与历史证据；具体结果再查[12](12_全任务实测与排错手册.md)。
4. 只读当前主题的专项讲义和证据，不重抓会议、重建数据集或打开平台。

用户报告练习网站多数入口已关闭，任务14的保留页面仍能练习且已经重置。重置范围、当前配置、新报告未经代理复核。历史任务14配置、R1八项/G1六项成功等均是**重置前历史结果**，不能称为用户现在的状态。代理平台操作继续暂停；学习问答不构成恢复训练、配置、仿真、读新报告或最终提交的授权。

## 2. 六步教学约定

每次围绕一个实际疑问，按需使用下列六步；简单问题可合并，不必机械输出六个标题。

| 顺序 | 应做到 | 示例 |
|---|---|---|
| ① 白话 | 先回答“它到底负责什么” | 回调像约好的通知：事情完成后系统才来敲门，不能刚发命令就假定完成 |
| ② 积木链 | 给可读的先后顺序或分支 | `收到导航目标 → 检查空闲 → 设置忙 → 发起导航 → 等到达回调 → 清忙 → 通知master` |
| ③ 接口 | 说清数据类型、来源、去向；涉及几何再写单位和坐标系 | `Navigation_Address` 是航点名字符串，不是整份任务字典，也不是像素坐标 |
| ④ 错例 | 展示一个貌似合理但会失败的接法 | 发起导航后立即发布完成，会让主流程在机器人没到时提前开始识别 |
| ⑤ 纠正 | 指出第一个错误环节和理由 | 完成通知放进实际导航完成回调，主流程再按对应状态推进 |
| ⑥ 检查 | 给一个可口述、可选作的小问题 | “机器人已到目标但主流程没动，先查回调还是先改地图？为什么？” |

默认用图形块、字段、连线与数据流讲。可以展示简短伪代码或一行公式来澄清语义，不先让用户安装 ROS、搭建开发环境或写完整程序。**不能保证正式题完全不涉及源码或公式**：培训涉及奖励函数、步态周期、刚度阻尼、经验缓存和 PPO 裁剪参数；应讲它们控制什么、改错会怎样，不把公式理解省掉。[依据：11运动章节](11_速通版完整学习路线.md)、[13证据及边界](13_正式赛题推断与备赛重点.md)。

问题需要额外信息时，优先问“你看到哪一个字段/第一步卡在哪里”；不索要密码、会话令牌、带认证信息的完整实验 URL。用户仅问概念时不要求提供截图。

## 3. 十二章节：都要了解，不按主责跳课

A/B/C 是备赛建议，不是官方分值划分。三人都要能复述完整链条；“我不是 C”不能成为不懂消息或坐标系的理由。每节掌握最低线是解释输入、处理、输出以及一个错例，而不是把全部参数背下来。

### S00｜整体任务链：先看谁把什么交给谁

- **目标：** 能画出“接到任务→到展区→运动/表演→感知→抓放→反馈→返回”的教学链，并指出实际顺序必须按正式题面。
- **易错点：** 四个正式模块“运动控制、定位导航、视觉感知、ROS集成”不等于任务14四节点 `master/nav/vision/arm`。一个节点可能调用多个模块，抓取也横跨视觉、坐标和机械臂。
- **白话与积木：** 模块像能力部门，节点像负责收发任务的岗位；`master派单 → nav带路 → vision找目标 → arm执行 → master确认下一步`。
- **追问可复制：** “S00：请把一个展会任务拆成每步输入和输出，并标明四模块与四节点分别落在哪里。”
- **口述检查：** 视觉返回物体框后，为什么不能直接宣布抓取完成？答：还缺深度/几何、位姿、变换、规划执行和结果反馈。
- **来源：** [01官方规则](01_官方规则梳理.md)、[11完整任务链](11_速通版完整学习路线.md)、[13预测](13_正式赛题推断与备赛重点.md)。具体展会链为教学假设。

### S01｜积木语法：连线表示流程，也要看事件和类型

- **目标：** 区分顺序块、条件分支、变量、函数与事件回调；知道“接上了”不代表数据类型、事件时机或保存状态正确。
- **易错点：** 连线上一块已发命令≠下一动作已完成；变量里存的值≠变量名字本身；字符串“false”≠布尔 `false`；节点≠函数。
- **积木链：** `事件触发 → 从消息取字段 → 存入同类型变量 → 判断条件 → 执行动作 → 等回调`。图形编辑仍是在表达逻辑和接口约定。
- **追问可复制：** “S01：我看见这个积木字段__，不知道该填常量、变量还是回调参数，请用一个正确接法和一个错接法解释。”
- **口述检查：** 为何不能把整份任务字典填进“航点名称”？答：该字段需要特定 key 对应的字符串值，不是字典对象。
- **来源：** [03节点/变量/字段](03_任务14实战攻略.md)、[07基础词汇](07_零基础第一课与ROS速查.md)。文字积木链是教学转述。

### S02｜运动 A：学的是怎样动作，不是地图怎么走

- **目标：** 分清观察、动作、奖励、重置、训练参数；区分训练出策略与加载策略推理。
- **易错点：** 只奖励不倒可能学到站住；误差正奖励可能鼓励偏离；训练步数多不自动代表正式评分高；步态周期、控制采样周期、学习率是不同量。
- **积木链：** `身体/关节状态和指令 → 策略模型 → 关节目标/控制器 → 运动结果`；训练时另有 `结果 → 奖励/终止 → 更新策略`。
- **追问可复制：** “S02：为什么有奖励和重置，还需要训练参数？请用站立、走路、跳舞各举一个区别。”
- **口述检查：** 导航给出前进速度后，谁负责让双足保持稳定？答：相应运动策略/控制器，导航规划本身不替代关节控制。
- **来源：** [10任务1—3要求](10_官方任务要求与评分.md)、[11运动与源码解释](11_速通版完整学习路线.md)、[12历史运动结果](12_全任务实测与排错手册.md)。具体参数不是跨场景唯一答案。

### S03｜视觉 A：先问输出是什么

- **目标：** 能区分分类类别、检测框、实例掩膜、视频动作标签、关键点规则；知道置信度与整体模型指标不同。
- **易错点：** 检测框不是三维抓取位姿；置信度高仍可能识别错；高 mAP 不证明抓放完成；训练、推理的类别/权重绑定不一致会破坏流程。
- **积木链：** `图像/视频 → 预处理 → 正确模型或规则 → 类别/框/掩膜/关键点 → 后续判断或几何处理`。
- **追问可复制：** “S03：分类、检测、分割对后面的机械臂各能提供什么，还缺什么？”
- **口述检查：** 模型给出“水壶0.86”，是不是空间坐标？答：这是类别和本次评分，位置需要框/掩膜，三维还要深度与内参等。
- **来源：** [10任务4—6](10_官方任务要求与评分.md)、[11视觉与指标](11_速通版完整学习路线.md)、[12视觉失败记录](12_全任务实测与排错手册.md)。

### S04｜建图定位 B：地图与“我在哪”分开看

- **目标：** 理解建图建立环境表示，定位估计机器人在地图中的位置和朝向；认识二维栅格与三维点云用途不同。
- **易错点：** 建图进度99%不等于准确度99%；有地图不等于已经定位；算法换了不能沿用另一个算法全部字段和经验。
- **积木链：** `传感器/里程计 → 建图 → 保存/预览地图`；导航时再 `地图 + 当前观测 → 定位结果`。
- **追问可复制：** “S04：地图已经做好，为何机器人还可能走偏？请按地图、定位、规划分开说明。”
- **口述检查：** 真实通道在地图上断了，应该先查什么？答：先检查地图覆盖/质量和表示，不能靠放宽到达阈值修复不存在的通道。
- **来源：** [10任务7—9](10_官方任务要求与评分.md)、[11导航](11_速通版完整学习路线.md)、[12任务7与9](12_全任务实测与排错手册.md)。算法命题线索另见[13](13_正式赛题推断与备赛重点.md)，仍属口述。

### S05｜导航 B：到点也要朝向对、路径可走

- **目标：** 理解航点位置/朝向、机器人尺寸与障碍膨胀、全局路径、局部避障、到达条件和完成反馈。
- **易错点：** 图钉放在桌上或墙里；只验位置不验方向；地图线看着没碰墙，却没给机身留空间；已发送导航命令就发完成。
- **积木链：** `目标航点 + 定位 + 地图 → 全局路径 → 局部控制/避障 → 到达判定 → 完成消息`。
- **追问可复制：** “S05：机器人到了桌边却看不到目标，怎样区分航点位置、朝向和视觉问题？”
- **口述检查：** 朝向误差很大但位置误差小，应直接放宽所有阈值吗？答：先核对目标朝向和可达姿态；题设到达条件不能擅自放松。
- **来源：** [10任务8—9](10_官方任务要求与评分.md)、[11导航](11_速通版完整学习路线.md)、[15模拟导航答案](15_模拟卷A标准答案与操作对照.md)。模拟地图阈值不冒充真实平台默认值。

### S06｜坐标标定 C：同一个点需要同一种“地址语言”

- **目标：** 区分像素、相机三维点、基座三维点与含方向的位姿；理解内参与外参/TF各解决什么。
- **易错点：** 像素直接加米；未知深度就算三维；TF重复一次；眼在手上/手外使用相同固定关系；点的三个数被当成完整6D抓取姿态。
- **积木链：** `像素 + 配准深度 + 内参 → 相机点/点云 → 位姿估计（若需要） → 正确方向TF → 目标坐标系位姿`。TF改变数值表达，不驱动机械臂。
- **追问可复制：** “S06：我看到Pose/Point_Cloud/Fpose，它们各是什么类型、当前在哪个坐标系？为什么有的分支变换一次，有的不再变换？”
- **口述检查：** 已经在基座坐标系的放置位姿，还要相机→基座变换吗？答：不要重复；先沿数据来源确认是否已经转过。
- **来源：** [07坐标例子](07_零基础第一课与ROS速查.md)、[03物体/颜色分支](03_任务14实战攻略.md)、[10抓取题眼手关系](10_官方任务要求与评分.md)。矩阵用本题含义，不跨题抄值。

### S07｜抓取 C：看到、算到、到得了、抓住是四步

- **目标：** 区分目标点云、抓取候选、逆运动学、碰撞检查/路径规划、机械臂运动和夹爪执行；抓取与放置使用同一持物手。
- **易错点：** 无候选却只加规划时间；有候选就认为必可达；机械臂移动完成等于物体抓住；左右臂与夹爪映射不配套。
- **积木链：** `目标点云 → 抓取位姿 → TF → 选臂与夹爪 → 解算/规划 → 移动完成回调 → 夹爪动作 → 按可用证据检查实际抓放`。
- **追问可复制：** “S07：没有合理抓取位姿、IK失败、规划失败、夹爪闭合但没拿住，分别先查哪里？”
- **口述检查：** 报告显示候选列表为空，优先调整运动速度吗？答：先查对象/点云/抓取模型及候选过滤，执行速度属于后面阶段。
- **来源：** [10任务10—12](10_官方任务要求与评分.md)、[12抓取报告](12_全任务实测与排错手册.md)、[03 arm流程](03_任务14实战攻略.md)。不凭教学规则发明平台不存在的物体附着传感器。

### S08｜ROS通信 C：消息袋子与问答窗口

- **目标：** 区分节点、发布者、订阅者、话题、服务端、请求、响应和回调；知道字段名字、类型和含义都须匹配。
- **易错点：** `_locate` 创建成普通订阅者；`Point_Cloud` 与 `Pcloud` 混写；`Pose` 与点云混用；自定义完成字段大小写不统一。
- **积木链：** 话题：`发送者发布 → 对应订阅回调`；服务：`请求 → 服务端处理 → 响应 → 请求方响应回调`。
- **追问可复制：** “S08：为什么导航用话题而视觉定位用服务？请从任务14实际字段讲，不要先讲整套ROS安装。”
- **口述检查：** `_locate` 返回 `Point_Cloud`，转发到 `_grab` 时字段叫哪个？答：实际任务14参考链使用 `Pcloud`；数据可以转存，名字不能漏核对。
- **来源：** [03接口表](03_任务14实战攻略.md)、[07 ROS速查](07_零基础第一课与ROS速查.md)。这是该练习约定，不是所有ROS系统必须用同一名称。

### S09｜状态回调 C：主流程在等谁

- **目标：** 根据当前状态确定等待导航/抓放完成还是视觉服务响应；分清发起与完成，理解状态更新和重复消息风险。
- **易错点：** 所有事件都让状态加一；把视觉等待状态放进 `_finish` 分支；没有回调也预先推进；把模拟A卷状态编号套到任务14。
- **积木链：** `当前状态 + 匹配事件 → 核对数据/成功条件 → 更新状态 → 发下一请求`。实际任务14状态2/5/8/10在等视觉响应，不能统一用导航/抓放完成消息推进。
- **追问可复制：** “S09：状态停在__，上一个动作是__，它现在到底在等哪个回调？请画出这一段来回消息。”
- **口述检查：** 收到一个无关或重复的完成消息就能开始下一段吗？答：应匹配正在等待的动作；简化布尔接口的区分能力有限，不凭空保证已去重。
- **来源：** [03任务14状态表](03_任务14实战攻略.md)、[07卡点表](07_零基础第一课与ROS速查.md)、[15模拟状态机](15_模拟卷A标准答案与操作对照.md)。模拟新增请求ID不是已证实可直接导入的平台字段。

### S10｜故障共同：找最早断点，不一次乱改十项

- **目标：** 将“没做成”变成第一条不满足的输入、数据、状态、执行或结果证据，再提出单因素验证。
- **易错点：** 模型高分就排除视觉；所有函数都执行就宣布成功；看到连线就认为已保存；计划改动与已经修复混写。
- **积木链：** `预期 → 实际 → 最早差异 → 最小检查 → 单项改动计划 → 对比验收`。当前只教学，不代理执行计划。
- **追问可复制：** “S10：预期__，已看到__，第一件没发生的是__。请列最先核对的两项，并说明哪些结论现在还不能下。”
- **口述检查：** 训练完成、模型指标高、函数执行、实际任务成功，哪一个能替代另一个？答：都不能，分别需要对应证据。
- **来源：** [12全任务实测与排错](12_全任务实测与排错手册.md)、[16故障诊断题](16_换题变体与故障诊断模拟.md)。

### S11｜三人协作共同：交接能用的接口和证据

- **目标：** 三人都知道模块依赖、输入输出、版本名、参数/字段含义、当前失败和统一验证的顺序。
- **易错点：** 同时编辑同一模块；交接只说“好了”；A不知道视觉还由谁负责；把进度条或看板勾选当队伍验收；提前点最终锁定提交。
- **积木链：** `读共同题面 → 分主责 → 约定接口/命名 → 各自自检 → 退出后交接 → 统一验证 → 按规则最终交卷`。训练保存与最终交卷不同。
- **追问可复制：** “S11：如果我是B，A和C交接给我时，我最少要问哪五件事？怎样确认不是只完成了模块内部配置？”
- **口述检查：** “模型训练完了”作为完整交接够不够？答：不够，还要版本/绑定、输入输出、已验证场景、未解决问题和下一环所需信息。
- **来源：** [01正式协作与提交纪律](01_官方规则梳理.md)、[05三人计划](05_两天冲刺与三人分工.md)、[11完整速通](11_速通版完整学习路线.md)。主责分配是建议；正式期间由队员独立完成。

## 4. 三个跨模块诊断范例

下面是基于课程接口设计的**教学推演**，不是任务14重置后的新运行结果。Chat可先给题干，用户要直接看答案时就完整解释，不强制等待答题。

### 范例一：已到桌边，机器人一直等待

**题干：** 按任务14状态约定，主状态已经从1变成2；机器人位于第一桌边，尚未看到抓取动作。用户说“是不是地图又错了？”

**判断：** 状态2正在等待第一轮视觉服务响应。导航曾推进到这一步，说明至少已发生了相关流程事件；这不能证明所有地图/朝向完美，但第一检查对象是视觉请求与返回，不先重做地图。

**按图形块追：** `master状态1收到完成 → 设置状态2 → 请求_locate(Detect_Type=物体, Detect_Name=目标) → vision检测与点云 → 服务端响应 → master视觉回调1 → 状态3并发布_grab`。

**最小检查顺序：** ① 请求目标名/类型与当前图像是否有效；② `_locate` 是否为服务且执行到响应；③ 响应回调是否绑定、返回点云是否被转成 `_grab.Pcloud`。如果图像根本看不到桌面，再回头查 B 的航点朝向、相机视角；不能用“先查视觉”排除上游的所有可能。

**口述追问：** “若状态其实仍是1，检查起点会怎样变？”答案：先沿导航目标、忙标志、到达回调、完成消息到主节点这条链检查。依据：[03状态表](03_任务14实战攻略.md)、[07卡点表](07_零基础第一课与ROS速查.md)。

### 范例二：能识别，手却伸向错误位置

**题干：** 目标颜色识别正确，视觉返回的放置 `Pose` 已在基座坐标系；arm 又做一次相机→基座 TF，随后夹爪朝错误位置运动。

**判断：** 首个已知错误是重复变换，不是提高检测置信度能解决的事。检测正确、三维几何正确、运动可达是不同环节。

**按图形块追：** `颜色中心像素 → 深度/内参转三维 → vision的TF到基座 → 服务Pose → master发布_deploy.Fpose → arm直接使用基座位姿 → 规划/运动`。

**小算例：** 纯教学假设相机与基座轴同向，平移为 `(0.2,0,0.8)m`，相机点为 `(0.3,0.1,0.2)m`。正确一次得到 `(0.5,0.1,1.0)m`；重复加一次变成 `(0.7,0.1,1.8)m`。真实 TF 通常还有旋转；这里只说明为何不能重复，不教用户把真实矩阵简化为平移。

**口述追问：** “物体抓取分支也一律禁止arm变换吗？”答案：不是。任务14物体分支给相机点云，arm估计抓取位姿后才做 TF；颜色分支已经转好。依据：[03两分支](03_任务14实战攻略.md)、[07坐标](07_零基础第一课与ROS速查.md)。

### 范例三：所有函数执行，最后仍没放进盒子

**题干：** 一个教学报告显示检测正确、机械臂运动函数有执行、放置回调也执行了，但物体落在盒外。用户问“是不是多等几秒就算完成？”

**判断：** 函数调用和回调发生不证明目标物已落在容器内。最早错误可能在放置目标、姿态、手臂/夹爪映射、释放位置或实际执行偏差；题干不足以确定唯一原因。

**按图形块追：** `颜色目标与相机数据 → 位姿及坐标系 → Fpose → 选择持物手 → 规划运动 → 放置位置与夹爪释放 → 实际结果`。

**最小检查顺序：** ① 抓取与放置 `Hand` 是否对应同一持物手、臂与夹爪是否配套；② `Fpose` 是否目标盒子且仅经过需要的一次 TF；③ 运动终点/释放时刻与实物结果是否吻合。平台没有提供的传感器或标志不能凭空补入。

**历史旁证与限制：** 重置前任务14确有G1黄盒释放未入、降速50%未改善的记录；它说明不能凭降速猜修复，不说明本教学题或用户重置后情况与它同因。依据：[12任务14报告](12_全任务实测与排错手册.md)、[03历史验证](03_任务14实战攻略.md)。

## 5. Chat怎样判断学会了多少

使用“未看／看过但说不清／能解释一个例子／能独立解释变化例子”记录知识状态，允许用户随时跳到不懂的一点。看板点击、答对选择题、复制标准答案只说明发生了这些动作；不能自动变成独立操作能力。

一次简短检查可用三问：① 这块输入是什么？② 输出给谁、单位或坐标系是什么？③ 这里错了会让后面哪一步先失败？用户能对变换后的例子回答，再记录该点已检查；不授予“比赛已通过”。

当用户要求速通，不以省略知识范围换速度：减少重复参数讲解，保留 S00—S11 每节的输入输出、关键错误和验收信号。训练全部模型、熟练操作和真实机器人成功不包含在一次理论速通承诺中。
